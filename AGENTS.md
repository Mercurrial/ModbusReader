# ModbusReader: правила для агентов

## Работа с проектом

- Прочитайте `ARCHITECTURE.md` и относящиеся к задаче модули и тесты. Источник истины — код.
- Работайте в тестовой ветке. Сохраняйте чужие незакоммиченные изменения. Не публикуйте релизы и не сливайте в `main` без поручения владельца.
- Делайте изменения в рамках задачи; исправления связи, дизайн и новые форматы разделяйте на проверяемые этапы.
- Сообщения владельцу пишите по-русски; имена Python API и форматов сохраняйте стабильными.

## Архитектурные ограничения

- Один владелец транспорта: I/O выполняется потоком ядра через очереди. GUI не открывает тот же порт самостоятельно.
- GUI-поток не должен ждать I/O, `QThread.wait`, `join` или `sleep`. Используйте сигналы завершения и отменяемые операции; `processEvents` не является исправлением блокировки.
- Новая асинхронная работа должна иметь владельца и путь остановки. Не обращайтесь к удалённым Qt-объектам; используйте `gui.qt_utils.later` или проверку lifetime.
- При изменении проекта/соединения учитывайте незавершённые операции, очереди и запоздавшие результаты старой сессии.
- Типы/области берите из `core.datatypes`, виды виджетов — из `core.dash_model`, транспорты — из `core.transports`. Не создавайте параллельные списки.
- Сохраняйте проверенный порядок байтов по умолчанию и точность INT64. Не преобразуйте целые через float.
- Сохраняйте загрузку старых файлов через миграции. Строгий контракт создания новых файлов не заменяет совместимые загрузчики.
- GUI-текст поддерживает RU/EN; цвета и иконки берутся из существующей темы и реестра.

## Контракт для ИИ и редактора

- `core.macro_api` — объявления функций макроса и общий AST-фильтр; runtime, справка и подсказки читают его.
- `core.authoring` — схемы и семантическая проверка новых документов. `core.authoring_cli` — офлайн CLI. Эти модули не импортируют Qt и не исполняют проверяемые макросы.
- `AI_GUIDE.md` описывает подготовку файлов, а `tools/check_project.py` проверяет проект через штатный загрузчик вместе с макросами из его папки. Строгая проверка дополняет этот путь.
- `tools/build_authoring.py` генерирует схемы, справочник, stubs и автономный skill из тех же источников. Генерируемые файлы не редактируйте вручную.
- После изменения контракта: `python tools/build_authoring.py`, затем `python tools/build_authoring.py --check` и тесты контракта.
- Skill хранится в `skills/modbusreader-authoring/`; ZIP для распространения создаётся сборщиком. Не включайте в него пользовательские настройки, карты устройств или секреты.
- Проверка синтаксиса/AST не доказывает корректность алгоритма, безопасность скрипта или соответствие реальному устройству. Документируйте границы проверки.

## Проверка

Окружение: Python 3.12, `.venv`; зависимости закреплены в `requirements-dev.txt`.

```powershell
.\.venv\Scripts\python -m pytest tests/test_authoring.py tests/test_macro_engine.py tests/test_macro_safety.py
.\.venv\Scripts\python tools/build_authoring.py --check
.\.venv\Scripts\python -m pytest -o faulthandler_timeout=30
```

- Для логических изменений добавляйте регрессионные тесты наблюдаемого поведения. Проверяйте ошибки, границы, совместимость и отсутствие побочных эффектов.
- Тесты не должны использовать реальные устройства, настройки пользователя или сеть без явно предусмотренного тестового стенда. `tests/conftest.py` изолирует настройки и Qt.
- Проверяйте GUI в Dark/Light и RU/EN, когда меняете видимую часть; для снимков есть `tools/ui_snapshots.py`.
- Не называйте прерванный или зависший прогон успешным. Указывайте выполненные команды, результат и ограничения.
