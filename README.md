# ModbusReader

Настольное приложение (PyQt6) для наладки и мониторинга приборов по
**Modbus RTU** — и как мастер, и как эмулятор прибора. Версия **2.2.0**.

Все экраны — в панели слева (сворачивается до значков); в шапке — проект,
параметры связи и кнопка «Подключить».

## Возможности

| Окно | Что делает |
|---|---|
| **Карта регистров** (Ctrl+1) | Циклический опрос, запись значений, масштабирование и подписи (enum), графики в реальном времени, поиск |
| **Редактор карты** (Ctrl+2) | Создание и правка карты регистров, импорт из CSV/Excel, перетаскивание строк, отмена/повтор |
| **Консоль** (Ctrl+3) | Журнал обмена и отправка сырых кадров с автоматическим CRC16 |
| **Сканер** (Ctrl+4) | Поиск устройств на линии и живых регистров на устройстве |
| **Сниффер** (Ctrl+5) | Пассивное прослушивание RS-485 со вторым адаптером, разбор кадров |
| **Дашборд** (Ctrl+6) | Мини-HMI: 14 типов виджетов, провода-автоматика, несколько экранов |
| **Снимки** (Ctrl+7) | «Что изменилось?»: снимок всех значений и сравнение |
| **Логгер** (Ctrl+8) | Многочасовая запись значений в CSV (Excel-совместимый, с ротацией) |
| **Slave** (Ctrl+9) | Эмулятор прибора: программа отвечает мастеру по открытой карте (FC 01–06, 15, 16) |
| **Наблюдение** (F6) | Плавающее окно с выбранными регистрами — видно с любого экрана |
| **Макросы** (Ctrl+M) | Python-скрипты, которые читают/пишут регистры и собирают таблицу; работают в фоне |

В правом нижнем углу — статистика линии: запросы, ответы, таймауты, ошибки
CRC, исключения, время ответа (щелчок — подробности).

Типы данных: SHORT, UINT16, BITS16, BCD16, LONG, UINT32, BCD32, FLOAT, INT64,
DOUBLE, STRING, BOOL и служебные области; порядок байт настраивается.
Таблицы Modbus: holding и input-регистры, coils и discrete inputs
(FC 01/02/03/04/05/06/16).

Проект (`.mbproj`) хранит подключение, карту регистров и все дашборды вместе.
Интерфейс — русский и английский, тёмная и светлая темы, 7 цветовых схем,
3 уровня контраста, 12 акцентов.

## Запуск из исходников

Требуется **Python 3.10+** (разработка ведётся на 3.12).

```bash
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python main.py
```

Linux/macOS: те же шаги (`source .venv/bin/activate`, `python main.py`).
На Linux пользователь должен состоять в группе `dialout` для доступа к
последовательным портам.

## Сборка .exe

Иконка и заставка лежат в `assets/`; перегенерировать их:
`python tools/make_icon.py`, `python tools/make_splash.py`. Сведения о версии
exe (Свойства → Подробно) берутся из `version.py` автоматически.

```bash
.venv\Scripts\pip install pyinstaller
.venv\Scripts\pyinstaller ModbusReader.spec          # оконная сборка (с иконкой)
.venv\Scripts\pyinstaller ModbusReader_debug.spec    # с консолью для отладки
```

## Файлы, которые пишет приложение

* `app_settings.json` — рядом с приложением (портативный режим). Если папка
  недоступна для записи (например, Program Files), настройки переезжают в
  `%APPDATA%/ModbusReader`. Запись атомарная, с копией `.bak` и
  восстановлением при повреждении.
* `modbusreader_errors.log` — в той же папке: трассировки непойманных ошибок
  (в оконной сборке консоли нет, без этого файла сбой нельзя расследовать).

## Тесты

```bash
.venv\Scripts\python -m pytest
```

Около 820 тестов, полностью headless (`QT_QPA_PLATFORM=offscreen` ставится
автоматически). Тесты никогда не читают и не пишут ваш настоящий
`app_settings.json`.
