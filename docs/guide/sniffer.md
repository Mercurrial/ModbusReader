# Сниффер

**Сниффер** (++ctrl+5++) слушает линию RS-485 и показывает каждый кадр
между **чужим** мастером (SCADA, контроллером, панелью) и приборами. Сам он
**не передаёт ни байта** — линия работает как обычно.

![Сниффер: время, адрес прибора, функция, тип кадра, данные и CRC](../images/sniffer.png)

## Подключение

Снифферу нужен **свой адаптер**, подключённый к той же паре A/B параллельно
линии. Порт, который занят опросом этой же программы, сниффер не откроет:
у порта может быть только один владелец.

1. Подключите второй USB-RS-485 адаптер к линии (A к A, B к B, GND к GND).
2. Откройте **Сниффер**, выберите **порт** этого адаптера и **скорость
   линии**. Чётность и стоп-биты берутся из **Настройки → Подключение**.
3. Нажмите **«Слушать»**.

Скорость должна совпадать со скоростью линии: на другой скорости кадры
развалятся на мусор с ошибками CRC.

## Что видно

| Колонка | Смысл |
|---|---|
| Время | Когда пришёл кадр |
| ID | Адрес прибора |
| Функция | Read Holding, Write Register… — см. [коды функций](../modbus/functions.md) |
| Тип | Запрос, ответ, исключение или мусор |
| Данные | Расшифровка: адрес, количество, значения |
| CRC | OK или BAD |

Наведите курсор на строку — подсказка покажет кадр целиком в hex.

Кадры программа делит по паузам на линии (правило 3,5 символа), проверяет
CRC и расшифровывает функции 01–06, 08, 15, 16, 22, 23. Исключения
подсвечены; кадр с неверной CRC помечен **BAD**.

## Для чего это нужно

- **Узнать карту без документации:** какие регистры и как часто читает
  SCADA — значит, они существуют и важны.
- **Разобраться, кто виноват:** мастер не шлёт запрос, прибор не отвечает
  или отвечает исключением.
- **Найти помехи:** много BAD CRC — проблема в линии (терминатор, общий
  провод, экран), а не в программе.
- **Проверить себя:** второй адаптер, подключённый к той же линии, покажет
  обмен самого ModbusReader «со стороны».

Сценарий целиком — в примере [Отладка линии](../examples/line-debugging.md).
