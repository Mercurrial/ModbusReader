# CRC-16 Modbus

Каждый кадр [Modbus RTU](rtu.md) заканчивается двумя байтами **CRC** —
контрольной суммой всех предыдущих байт. Приёмник считает её заново и
сравнивает с принятой: не совпало — кадр испорчен помехой и молча
отбрасывается. Посчитать CRC готового кадра можно в
[онлайн-калькуляторе](../tools/crc.md); здесь — как она устроена и как
посчитать её в своей программе.

| Параметр | Значение |
|---|---|
| Название | CRC-16/MODBUS |
| Полином | 0x8005 (x¹⁶ + x¹⁵ + x² + 1); в «отражённом» виде — **0xA001** |
| Начальное значение | **0xFFFF** |
| Отражение входа и выхода | да (биты обрабатываются младшим вперёд) |
| Финальный XOR | нет (0x0000) |
| Порядок в кадре | **младший байт первым** |
| Контрольное значение | CRC строки `123456789` = `0x4B37` |

!!! note "Не путать с другими CRC-16"
    У CRC-16 десятки вариантов с тем же полиномом, но другим начальным
    значением или порядком битов: CRC-16/ARC начинает с 0x0000,
    CRC-16/CCITT использует полином 0x1021. С Modbus совпадает только
    CRC-16/MODBUS — проверяйте по контрольному значению `0x4B37`.

## Алгоритм { #algorithm }

1. Регистр CRC = `0xFFFF`.
2. Для каждого байта кадра (кроме самих байт CRC):
    1. CRC = CRC XOR байт (байт ложится в младшие 8 бит).
    2. Восемь раз: если младший бит CRC равен 1 — сдвинуть CRC вправо на 1
       и сделать XOR с `0xA001`; иначе — просто сдвинуть вправо на 1.
3. Результат — 16-битное число. В кадр сначала пишется **младший** байт,
   потом старший.

### Пример по шагам { #example }

Кадр запроса `01 03 00 00 00 02`. Первый байт `0x01`:

```text
CRC = FFFF XOR 0001 = FFFE
шаг  младший бит  действие                 CRC
 1        0       сдвиг                    7FFF
 2        1       сдвиг, XOR A001          9FFE
 3        0       сдвиг                    4FFF
 4        1       сдвиг, XOR A001          87FE
 5        0       сдвиг                    43FF
 6        1       сдвиг, XOR A001          81FE
 7        0       сдвиг                    40FF
 8        1       сдвиг, XOR A001          807E
```

Так же обрабатываются остальные пять байт; в конце CRC = `0x0BC4`. В кадр
он идёт младшим байтом вперёд — `C4 0B`:

```text
01 03 00 00 00 02 C4 0B
```

## Код { #code }

Все примеры ниже проверены: для кадра `01 03 00 00 00 02` дают `C4 0B`, для
строки `123456789` — `0x4B37`.

=== "C"

    ```c
    #include <stdint.h>
    #include <stddef.h>

    uint16_t modbus_crc16(const uint8_t *data, size_t len)
    {
        uint16_t crc = 0xFFFF;
        for (size_t i = 0; i < len; i++) {
            crc ^= data[i];
            for (int bit = 0; bit < 8; bit++) {
                if (crc & 0x0001)
                    crc = (crc >> 1) ^ 0xA001;
                else
                    crc >>= 1;
            }
        }
        return crc;
    }

    /* дописать CRC в кадр (младший байт первым);
       в буфере должно быть место ещё на 2 байта */
    size_t add_crc(uint8_t *frame, size_t len)
    {
        uint16_t crc = modbus_crc16(frame, len);
        frame[len]     = crc & 0xFF;
        frame[len + 1] = crc >> 8;
        return len + 2;
    }
    ```

=== "C, табличный"

    ```c
    #include <stdint.h>
    #include <stddef.h>

    static uint16_t table[256];

    void modbus_crc16_init(void)          /* вызвать один раз при старте */
    {
        for (int n = 0; n < 256; n++) {
            uint16_t crc = (uint16_t)n;
            for (int bit = 0; bit < 8; bit++)
                crc = (crc & 1) ? (crc >> 1) ^ 0xA001 : crc >> 1;
            table[n] = crc;
        }
    }

    uint16_t modbus_crc16_fast(const uint8_t *data, size_t len)
    {
        uint16_t crc = 0xFFFF;
        while (len--)
            crc = (crc >> 8) ^ table[(crc ^ *data++) & 0xFF];
        return crc;
    }
    ```

    Табличный вариант в несколько раз быстрее: один поиск в таблице вместо
    восьми сдвигов на байт. На микроконтроллере таблицу можно сразу
    положить во флеш как константу — первые значения: `0x0000, 0xC0C1,
    0xC181, 0x0140…`, последнее — `0x4040`.

=== "Python"

    ```python
    def modbus_crc16(data: bytes) -> int:
        crc = 0xFFFF
        for byte in data:
            crc ^= byte
            for _ in range(8):
                if crc & 1:
                    crc = (crc >> 1) ^ 0xA001
                else:
                    crc >>= 1
        return crc


    def with_crc(frame: bytes) -> bytes:
        """Кадр с CRC в конце, младший байт первым."""
        return frame + modbus_crc16(frame).to_bytes(2, "little")


    print(with_crc(bytes.fromhex("01 03 00 00 00 02")).hex(" ").upper())
    # 01 03 00 00 00 02 C4 0B
    ```

=== "JavaScript"

    ```javascript
    function modbusCrc16(bytes) {
      let crc = 0xFFFF;
      for (const b of bytes) {
        crc ^= b;
        for (let i = 0; i < 8; i++) {
          crc = (crc & 1) ? (crc >>> 1) ^ 0xA001 : crc >>> 1;
        }
      }
      return crc;
    }

    function withCrc(bytes) {
      const crc = modbusCrc16(bytes);
      return [...bytes, crc & 0xFF, crc >>> 8];   // младший байт первым
    }

    withCrc([0x01, 0x03, 0x00, 0x00, 0x00, 0x02]);
    // [1, 3, 0, 0, 0, 2, 196, 11]  ->  01 03 00 00 00 02 C4 0B
    ```

## Проверка принятого кадра { #check }

Удобное свойство: если посчитать CRC по **всему** кадру вместе с его двумя
байтами CRC, результат будет `0x0000`. Поэтому проверка сводится к одной
строке:

```python
def crc_ok(frame: bytes) -> bool:
    return len(frame) >= 4 and modbus_crc16(frame) == 0
```

Минимальная длина 4 байта — адрес, функция и CRC; кадр короче — заведомо
испорчен.

## Частые ошибки { #mistakes }

| Симптом | Причина |
|---|---|
| CRC «почти правильная» — байты переставлены | Записали старший байт первым. В Modbus RTU — младший первым |
| Прибор молчит, хотя «кадр верный» | CRC посчитана по символам hex-строки («01 03 …» как текст), а не по байтам |
| CRC не совпадает ни с одним калькулятором | Начальное значение 0x0000 вместо 0xFFFF (это CRC-16/ARC) |
| Не сходится только на некоторых кадрах | Знаковый тип: `char` вместо `uint8_t` в C, отрицательные байты в Java/C# |
| В Modbus TCP прибор отвечает ошибкой | В [Modbus TCP](tcp.md) CRC нет — целостность обеспечивает TCP. CRC есть только в [RTU по TCP](rtu-over-tcp.md) |

В [Modbus ASCII](index.md#variants) вместо CRC используется LRC —
однобайтовая сумма, считаемая по-другому.

## Почему CRC, а не сумма байт { #why }

Простая сумма не замечает перестановку байт и многие двойные ошибки. CRC-16
гарантированно обнаруживает любую одиночную и двойную битовую ошибку, любое
нечётное число ошибок и любую пачку ошибок длиной до 16 бит подряд — именно
так обычно и выглядят помехи на линии RS-485. Вероятность пропустить
случайное искажение — около 1 из 65 536.

## В ModbusReader { #modbusreader }

ModbusReader считает и проверяет CRC сам: в [консоли](../guide/console.md)
достаточно набрать кадр без контрольной суммы — программа добавит её перед
отправкой. Ответы с неверной CRC попадают в счётчик **«Ошибки CRC»**
[статистики линии](../guide/register-map.md), а [сниффер](../guide/sniffer.md) помечает их в чужом
обмене — частые ошибки CRC указывают на помехи, плохую проводку или
неверную чётность (см. [Решение проблем](../troubleshooting.md)).
