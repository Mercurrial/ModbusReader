# Что такое Modbus RTU

**Modbus** — протокол обмена данными между контроллером или компьютером и
приборами: датчиками, регуляторами, частотными преобразователями, счётчиками.
Он появился в 1979 году и до сих пор самый распространённый в промышленной
автоматике: простой, открытый и поддерживается почти всеми производителями.

**Modbus RTU** — вариант протокола для последовательной линии (обычно
RS-485): данные идут в двоичном виде, каждый кадр защищён контрольной суммой
CRC16. ModbusReader работает именно с ним.

## Мастер и подчинённые

На линии один **мастер** (master, клиент) и до 247 **подчинённых** приборов
(slave, сервер). Говорит только мастер: он отправляет запрос конкретному
прибору, и только этот прибор отвечает. Сами приборы никогда не начинают
обмен.

- ModbusReader в обычном режиме — **мастер**: опрашивает прибор по карте
  регистров.
- В режиме [эмулятора](../guide/slave.md) — **подчинённый**: отвечает
  другому мастеру как прибор.
- В режиме [сниффера](../guide/sniffer.md) — никто: только слушает чужой
  обмен.

## Данные прибора — регистры

Всё, что прибор показывает и принимает, лежит в четырёх таблицах:

| Таблица | Что хранит | Доступ | Пример |
|---|---|---|---|
| Coils (0x) | Биты | чтение и запись | Включить вентилятор |
| Discrete inputs (1x) | Биты | только чтение | Дверь открыта |
| Input registers (3x) | 16-битные слова | только чтение | Измеренный ток |
| Holding registers (4x) | 16-битные слова | чтение и запись | Уставка температуры |

Каждый регистр — 16 бит. Числа больше (32-битные целые, FLOAT) занимают два
или четыре соседних регистра. Подробно — в разделах
[Области и адреса](addressing.md) и [Типы данных и порядок байт](data-types.md).

## Кадр Modbus RTU

Каждый запрос и ответ — один кадр:

| Адрес прибора | Код функции | Данные | CRC16 |
|:---:|:---:|:---:|:---:|
| 1 байт | 1 байт | 0–252 байта | 2 байта |

- **Адрес** — 1…247; 0 — широковещательный (только запись, приборы не
  отвечают).
- **Код функции** — что сделать: прочитать holding-регистры (03), записать
  один регистр (06) и т. д. Список — в разделе [Функции и ошибки](functions.md).
- **CRC16** — контрольная сумма, младший байт первым. Прибор молча
  отбрасывает кадр с неверной CRC. Посчитать CRC любого кадра —
  [калькулятор CRC](../tools/crc.md).

Кадры разделяет **тишина на линии не короче 3,5 символа** — по ней приёмник
понимает, где кончился кадр. На 9600 бод это около 4 мс, на скоростях выше
19200 стандарт фиксирует 1,75 мс.

### Пример: чтение двух регистров

Мастер просит прибор с адресом 1 прочитать 2 holding-регистра, начиная с
адреса 0:

```text
01 03 00 00 00 02 C4 0B
|  |  +-+-+ +-+-+ +-+-+
|  |    |     |     +-- CRC16
|  |    |     +-------- количество регистров: 2
|  |    +-------------- начальный адрес: 0x0000
|  +------------------- функция 03: чтение holding-регистров
+---------------------- адрес прибора: 1
```

Прибор отвечает:

```text
01 03 04 41 C4 CC CD 3B 67
|  |  |  +----+----+ +-+-+
|  |  |       |        +-- CRC16
|  |  |       +----------- 4 байта данных: 0x41C4, 0xCCCD
|  |  +------------------- число байт данных: 4
|  +---------------------- функция 03
+------------------------- адрес прибора: 1
```

Два регистра `41C4 CCCD` — это число FLOAT **24.6** в порядке ABCD. Если
прибор не может выполнить запрос, он отвечает **исключением**: код функции с
установленным старшим битом (`0x83`) и кодом ошибки — например,
`01 83 02 C0 F1` означает «недопустимый адрес данных».

В ModbusReader такой разбор видно в журнале обмена внизу окна, а любой кадр
можно отправить вручную из [консоли](../guide/console.md) — CRC программа
посчитает сама.

## RTU, ASCII и TCP

| | Modbus RTU | Modbus ASCII | Modbus TCP |
|---|---|---|---|
| Среда | RS-485, RS-232 | RS-485, RS-232 | Ethernet |
| Формат | двоичный | текстовый (hex-символы) | двоичный |
| Контроль | CRC16 | LRC | нет (это делает TCP) |
| Адрес прибора | в каждом кадре | в каждом кадре | Unit ID в заголовке MBAP |

Набор функций и регистров у всех трёх одинаковый — отличается только
«упаковка». ModbusReader работает с **Modbus RTU** по последовательному порту.
