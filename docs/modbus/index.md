# Протокол Modbus

**Modbus** — открытый протокол обмена данными между контроллером или
компьютером и промышленными приборами: датчиками, счётчиками, регуляторами,
частотными преобразователями, модулями ввода-вывода. Его создала компания
Modicon в 1979 году для своих программируемых контроллеров, а сегодня это
самый распространённый протокол в промышленной автоматике и
диспетчеризации: он простой, бесплатный и поддерживается почти всеми
производителями.

| Свойство | Modbus |
|---|---|
| Тип | Прикладной протокол «запрос — ответ» |
| Появился | 1979, Modicon (сейчас — Schneider Electric) |
| Кто развивает | Modbus Organization, с 2004 года |
| Основные варианты | [Modbus RTU](rtu.md), Modbus ASCII, [Modbus TCP](tcp.md) |
| Среда | RS-485, RS-232, Ethernet |
| Адресов на линии | 247 (RTU и ASCII) |
| Порт TCP | 502; 802 — защищённый Modbus/TCP Security |
| Лицензия | Открытый, без лицензионных отчислений |

## Как устроен обмен { #how-it-works }

Modbus построен по схеме **«запрос — ответ»**. Одна сторона — **клиент**
(исторически **мастер**, master) — посылает запрос; другая — **сервер**
(**подчинённый**, slave) — выполняет его и отвечает. Сервер никогда не
начинает обмен сам: если ему есть что сообщить, клиент должен об этом
спросить. Поэтому вся работа с Modbus — это **опрос**: мастер по кругу
читает нужные значения.

```text
  Мастер (ПК, контроллер, SCADA)
     |  запрос: "прибор 5, прочитай регистры 0-9"
     v
  ----+-----------+-----------+-----------+----  линия RS-485
      |           |           |           |
   прибор 1    прибор 2    прибор 5    прибор 7
                              |
     ^  ответ: "вот 10 регистров" (отвечает только прибор 5)
```

- На последовательной линии (RS-485) **мастер один**, подчинённых — до 247.
  Каждый запрос адресован одному прибору по его адресу 1…247, и отвечает
  только он. Адрес 0 — широковещательный: запрос получают все, не отвечает
  никто.
- В сети (Modbus TCP) клиентов может быть несколько: каждый открывает своё
  TCP-соединение с прибором.

В 2020 году Modbus Organization заменила в документах пару «master/slave» на
«client/server». В технической литературе и в меню приборов по-прежнему
встречаются оба варианта — это одно и то же.

## Данные: четыре таблицы { #data-model }

Всё, что прибор показывает и принимает, Modbus представляет как четыре
таблицы:

| Таблица | Что хранит | Доступ | Нотация | Пример |
|---|---|---|:---:|---|
| Coils | биты | чтение и запись | 0x | Включить насос |
| Discrete inputs | биты | только чтение | 1x | Дверь открыта |
| Input registers | 16-битные слова | только чтение | 3x | Измеренный ток |
| Holding registers | 16-битные слова | чтение и запись | 4x | Уставка температуры |

В каждой таблице до 65 536 элементов с адресами 0…65535. **Регистр** — это
16-битное слово, и других типов данных протокол не знает: числа FLOAT, 32- и
64-битные целые, строки производители раскладывают по нескольким соседним
регистрам — каждый по-своему. Отсюда главные трудности при наладке:

- **Адреса.** В документации пишут «регистр 40001», а в кадре стоит адрес 0.
  Почему и как переводить — [Области и адреса](addressing.md).
- **Порядок байт.** Одно и то же число FLOAT разные приборы кладут в
  регистры в порядке ABCD, CDAB, BADC или DCBA —
  [Типы данных и порядок байт](data-types.md).
- **Масштаб.** Температура 23,5 °C часто передаётся как целое 235 с
  множителем 0,1 — [масштаб и смещение](data-types.md#scaling).

Что лежит в каких регистрах конкретного прибора, описывает его **карта
регистров** — таблица в руководстве производителя. Без неё прочитать прибор
можно, но понять, что значат числа, — нет.

## Функции { #functions }

Что сделать с данными, говорит **код функции** — второй байт кадра. Самые
используемые:

| Код | Функция | Что делает |
|:---:|---|---|
| 01 | Read Coils | Читает биты (coils) |
| 02 | Read Discrete Inputs | Читает дискретные входы |
| 03 | Read Holding Registers | Читает holding-регистры — самая частая функция |
| 04 | Read Input Registers | Читает input-регистры |
| 05 | Write Single Coil | Включает или выключает один бит |
| 06 | Write Single Register | Записывает один регистр |
| 15 (0F) | Write Multiple Coils | Записывает несколько битов |
| 16 (10) | Write Multiple Registers | Записывает несколько регистров |
| 23 (17) | Read/Write Multiple Registers | Пишет и читает за один запрос |
| 43/14 (2B/0E) | Read Device Identification | Производитель, модель, версия прибора |

Коды 65–72 и 100–110 отданы производителям под собственные функции. Полный
справочник с форматами запросов — [Функции и коды ошибок](functions/index.md).

**Сколько за раз.** Один запрос читает до 125 регистров или 2000 битов и
пишет до 123 регистров или 1968 битов. Больше — несколькими запросами.

## Ошибки: исключения { #exceptions }

Если прибор понял запрос, но выполнить не может, он отвечает
**исключением**: возвращает код функции с установленным старшим битом
(03 → 0x83) и код ошибки. Если же прибор запрос не понял (чужой адрес,
неверная контрольная сумма), он **молчит**, и мастер получает таймаут.

| Код | Название | Что обычно значит |
|:---:|---|---|
| 01 | Illegal Function | Прибор не поддерживает эту функцию |
| 02 | Illegal Data Address | Нет регистра с таким адресом (или блок выходит за край) |
| 03 | Illegal Data Value | Недопустимое значение или количество |
| 04 | Server Device Failure | Внутренняя ошибка прибора |
| 05 | Acknowledge | Принято, выполняется долго — спросите позже |
| 06 | Server Device Busy | Прибор занят — повторите позже |
| 08 | Memory Parity Error | Ошибка памяти при чтении файла |
| 0A | Gateway Path Unavailable | Шлюз не может связаться с сетью за ним |
| 0B | Gateway Target Device Failed to Respond | Прибор за шлюзом не ответил |

Что проверять при каждой ошибке — в разделах
[Исключения](functions/index.md#exceptions) и
[Решение проблем](../troubleshooting.md).

## Варианты Modbus { #variants }

Функции и регистры у всех вариантов одни и те же — различается
«упаковка»: как кадр передаётся по линии, как указан адрес прибора и как
проверяется целостность.

| Вариант | Среда | Кадр | Контроль | Где встречается |
|---|---|---|---|---|
| [Modbus RTU](rtu.md) | RS-485, RS-232 | двоичный, границы — паузы | CRC16 | Подавляющее большинство приборов |
| Modbus ASCII | RS-485, RS-232 | текст: `:` … CR LF | LRC | Старые приборы, модемные линии |
| [Modbus TCP](tcp.md) | Ethernet | заголовок MBAP + PDU | средствами TCP | Контроллеры, шлюзы, сетевые приборы |
| [RTU по TCP](rtu-over-tcp.md) | Ethernet | кадр RTU целиком в TCP | CRC16 | Преобразователи RS-485 ↔ Ethernet |
| Modbus UDP | Ethernet | как TCP, но по UDP | нет | Редко, вне официальной спецификации |
| Modbus/TCP Security | Ethernet | Modbus TCP внутри TLS | TLS | Новые системы с требованиями к защите |
| Modbus Plus | своя шина | закрытый, с передачей маркера | — | Устаревшие системы Modicon |

Есть и расширения производителей — например, **Enron Modbus** с
32-битными регистрами для расходомеров газа. С обычным Modbus они
совместимы лишь частично.

### PDU и ADU { #pdu-adu }

Спецификация делит кадр на две части:

- **PDU** (Protocol Data Unit) — код функции и данные. Одинаков во всех
  вариантах, не длиннее 253 байт.
- **ADU** (Application Data Unit) — PDU плюс адресация и проверка, своя у
  каждого варианта.

```text
Modbus RTU:  [адрес 1 Б][  PDU: функция + данные  ][CRC 2 Б]   до 256 байт
Modbus TCP:  [MBAP 7 Б ][  PDU: функция + данные  ]            до 260 байт
```

Поэтому шлюз RTU ↔ TCP не разбирает данные: он снимает одну «обёртку» и
надевает другую.

## Физический уровень: RS-485 и Ethernet { #physical }

Modbus — протокол, а не интерфейс: он описывает, *что* передаётся, а
провода и уровни сигналов задаёт физический интерфейс.

- **RS-485** — главная среда для Modbus RTU. Две линии A и B (витая пара),
  полудуплекс, до 1200 м на скоростях до ~100 кбит/с, до 32 стандартных
  нагрузок на сегмент без повторителя. На концах линии — терминаторы
  120 Ом, приборы подключаются шлейфом, без длинных отводов и «звёзд».
  Как подключить компьютер — [Подключение к прибору](../connect.md).
- **RS-232** — точка-точка, один прибор на порт, до ~15 м. Встречается у
  старых приборов и модемов.
- **Ethernet** — для Modbus TCP: обычная сеть, IP-адрес, порт 502.

**Параметры последовательного порта** должны совпадать у мастера и всех
приборов на линии: скорость (чаще 9600 или 19200 бод), чётность и
стоп-биты (по стандарту 8E1, на практике часто 8N1). Подробно — в разделе
[Modbus RTU](rtu.md#serial).

## Как выглядит обмен { #example }

Мастер читает у прибора с адресом 1 два holding-регистра начиная с
адреса 0 — функция 03:

```text
Запрос:  01 03 00 00 00 02 C4 0B
Ответ:   01 03 04 41 C4 CC CD 3B 67
```

В ответе 4 байта данных — регистры `41C4` и `CCCD`, вместе это число
FLOAT 24.6. Разбор по байтам — в разделе [Modbus RTU](rtu.md#example), а
любой свой кадр можно расшифровать [онлайн](../tools/crc.md).

## Ограничения { #limits }

Простота Modbus — и его сила, и его слабость:

- **Только опрос.** Прибор не сообщает о событии сам — мастер узнает о нём
  при следующем чтении. Чем больше приборов и регистров, тем реже каждый
  опрашивается.
- **Нет типов и описаний данных.** Протокол передаёт 16-битные слова; что они
  значат, известно только из документации прибора.
- **Нет защиты.** Классический Modbus не проверяет, кто прислал команду, и не
  шифрует данные. Защиту дают изоляция сети или Modbus/TCP Security.
- **Один мастер на линии RS-485.** Два мастера на одной линии мешают друг
  другу.
- **Небольшие пакеты.** До 125 регистров за запрос.

## Modbus и другие протоколы { #comparison }

| | Modbus | Profibus DP | CANopen | BACnet | OPC UA |
|---|---|---|---|---|---|
| Где | Везде, от счётчиков до ПЛК | Заводская автоматика (Siemens) | Машины, приводы, транспорт | Автоматизация зданий | Обмен между системами и в облако |
| Среда | RS-485, Ethernet | RS-485 | CAN | RS-485 (MS/TP), Ethernet | Ethernet |
| Модель данных | Регистры и биты | Циклические блоки по описанию GSD | Словарь объектов | Объекты со свойствами | Информационная модель с типами |
| Сложность | Минимальная | Высокая | Средняя | Средняя | Высокая |
| Стандарт | Открытая спецификация modbus.org | IEC 61158, PI | CiA 301, EN 50325-4 | ASHRAE 135, ISO 16484-5 | IEC 62541 |

Modbus выбирают, когда нужно просто и дёшево связать разнородные приборы:
его поддерживает почти всё, а для наладки хватает ноутбука и USB-адаптера.
Часто Modbus работает «внизу» — на уровне приборов, — а данные дальше уходят
в SCADA или OPC UA через шлюз.

## Где применяется { #usage }

- **Учёт энергии:** электросчётчики, теплосчётчики, расходомеры.
- **Приводы:** частотные преобразователи и устройства плавного пуска.
- **Регуляторы и датчики:** температура, давление, влажность, уровень.
- **Модули ввода-вывода** — дискретные и аналоговые сигналы для ПЛК.
- **Солнечная энергетика:** инверторы, контроллеры заряда, BMS аккумуляторов.
- **Здания и ЖКХ:** вентиляция, котельные, ИТП, диспетчеризация.
- **Умный дом и IoT:** шлюзы в MQTT, Home Assistant, контроллеры Wiren Board.

## Как начать работать с Modbus { #getting-started }

1. **Найдите в руководстве прибора** раздел Modbus: адрес по умолчанию,
   скорость, чётность и карту регистров.
2. **Подключитесь:** к RS-485 — через USB-RS-485 адаптер (A к A, B к B), к
   сетевому прибору — по IP-адресу. Подробно —
   [Подключение к прибору](../connect.md).
3. **Прочитайте один регистр** из карты, например функцией 03. Ответ пришёл —
   связь есть; таймаут — проверьте проводку и параметры порта.
4. **Разберитесь со значениями:** адреса, порядок байт, масштаб.
5. **Опишите все нужные регистры** — и опрашивайте их по кругу.

## Частые вопросы { #faq }

??? question "Modbus — это интерфейс или протокол?"
    Протокол. Он описывает, какие байты передаются и что они значат.
    Интерфейс — это RS-485, RS-232 или Ethernet: провода, уровни сигналов,
    разъёмы. Фраза «прибор с интерфейсом RS-485 и протоколом Modbus RTU»
    говорит и о том, и о другом.

??? question "Чем Modbus RTU отличается от Modbus TCP?"
    Данные и функции одинаковые. RTU работает по последовательной линии
    (RS-485), адрес прибора стоит в каждом кадре, целостность проверяет CRC16.
    TCP работает по Ethernet, вместо CRC — заголовок MBAP с Unit ID, а
    доставку гарантирует сам TCP. Подробно — [Modbus TCP](tcp.md).

??? question "Сколько приборов можно подключить к одной линии?"
    Адресов — 247. Но стандартный передатчик RS-485 «тянет» 32 нагрузки;
    приборы с драйверами 1/4 или 1/8 нагрузки позволяют подключить 128 или 256
    приборов на сегмент. Больше — через повторитель. На практике ограничивает
    и время опроса: чем больше приборов, тем реже каждый опрашивается.

??? question "Какая скорость у Modbus?"
    Modbus RTU обычно работает на 9600 или 19200 бод, многие приборы
    поддерживают 38400–115200. Опрос одного регистра на 9600 бод занимает
    не меньше 20 мс: запрос, пауза, время реакции прибора и ответ. Modbus TCP ограничен
    скоростью ответа прибора, а не сети.

??? question "Почему регистр 40001 читается по адресу 0?"
    «40001» — это нотация Modicon: цифра 4 обозначает таблицу holding-регистров,
    а нумерация начинается с единицы. В кадре стоит адрес с нуля без
    префикса. Подробно — [Области и адреса](addressing.md).

??? question "Нужна ли лицензия, чтобы использовать Modbus?"
    Нет. Спецификации опубликованы на modbus.org и бесплатны, отчислений
    за использование протокола нет.

??? question "Что значит «исключение 02»?"
    Прибор получил запрос, но регистра с таким адресом у него нет — или
    запрошенный блок выходит за край существующих регистров. Чаще всего
    адрес сдвинут на единицу или взят из таблицы 3x вместо 4x. Подробно —
    [Исключения](functions/index.md#exceptions).
