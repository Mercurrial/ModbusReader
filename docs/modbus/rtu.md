# Modbus RTU

**Modbus RTU** — вариант [протокола Modbus](index.md) для последовательной
линии, обычно RS-485. Данные идут в двоичном виде, каждый кадр защищён
контрольной суммой CRC16. Это самый распространённый вид Modbus: так
общаются счётчики, датчики, регуляторы и частотные преобразователи.

## Мастер и подчинённые

На линии один **мастер** (master, в новой терминологии — клиент) и до 247
**подчинённых** приборов (slave, сервер). Говорит только мастер: он
отправляет запрос конкретному прибору, и только этот прибор отвечает. Сами
приборы никогда не начинают обмен и не слышат ответов друг друга как
запросов.

| Адрес | Назначение |
|:---:|---|
| 0 | Широковещательный: запрос получают все, никто не отвечает |
| 1…247 | Адреса приборов |
| 248…255 | Зарезервированы |

Широковещательно имеет смысл только писать (например, синхронизировать
время на всех приборах) — прочитать так ничего нельзя, ведь ответа нет.

## Кадр Modbus RTU { #frame }

Каждый запрос и ответ — один кадр:

| Адрес прибора | Код функции | Данные | CRC16 |
|:---:|:---:|:---:|:---:|
| 1 байт | 1 байт | 0–252 байта | 2 байта |

- **Адрес** — кому запрос; в ответе прибор ставит свой адрес.
- **Код функции** — что сделать: прочитать holding-регистры (03), записать
  один регистр (06) и т. д. Список — в разделе [Функции и ошибки](functions.md).
- **Данные** — адрес первого регистра, количество, значения; состав зависит
  от функции.
- **CRC16** — контрольная сумма всех предыдущих байт кадра, **младший байт
  первым**. Прибор молча отбрасывает кадр с неверной CRC. Посчитать CRC любого
  кадра — [калькулятор CRC](../tools/crc.md).

Кадр целиком — не длиннее **256 байт**. Отсюда и пределы на одну операцию:
не больше 125 регистров за одно чтение и 123 за одну запись.

Часть кадра от кода функции до данных включительно (без адреса и CRC)
называется **PDU** — она одинакова в RTU, ASCII и TCP. Весь кадр с адресом и
CRC — **ADU**.

## Паузы: 1,5 и 3,5 символа { #timing }

В кадре RTU нет ни начального, ни конечного байта — границы задаёт тишина
на линии:

- **Между кадрами — не меньше 3,5 символа** (t3.5). По этой паузе приёмник
  понимает, что кадр кончился.
- **Внутри кадра — не больше 1,5 символа** (t1.5) между байтами. Если пауза
  длиннее, кадр считается испорченным.

Символ на линии — 11 бит: старт, 8 бит данных, бит чётности (или второй
стоп-бит) и стоп. Отсюда время:

| Скорость, бод | Символ | t1.5 | t3.5 |
|---:|---:|---:|---:|
| 2400 | 4,58 мс | 6,88 мс | 16,04 мс |
| 4800 | 2,29 мс | 3,44 мс | 8,02 мс |
| 9600 | 1,15 мс | 1,72 мс | 4,01 мс |
| 19200 | 0,57 мс | 0,86 мс | 2,01 мс |
| выше 19200 | — | 0,75 мс | 1,75 мс |

На скоростях выше 19200 бод стандарт фиксирует паузы, а не считает их от
скорости — иначе их не успевал бы отмерить простой контроллер.

!!! tip "Паузы и компьютер"
    USB-адаптеры и операционная система собирают принятые байты в пачки и
    отдают их программе с задержкой, поэтому мастер на ПК не может отмерить
    t1.5 с точностью до миллисекунды. Программы на ПК обычно узнают конец
    ответа по его длине — она понятна по первым байтам — и по паузе заметно
    длиннее 3,5 символа. ModbusReader делает и то, и другое, поэтому
    медленный прибор с паузами внутри ответа его не сбивает.

## Параметры порта { #serial }

Чтобы мастер и прибор поняли друг друга, у них должны совпадать:

- **Скорость** — чаще всего 9600 или 19200 бод; стандарт требует от каждого
  прибора 9600 и 19200, по умолчанию — 19200.
- **Формат символа** — 8 бит данных, чётность и стоп-биты. По стандарту по
  умолчанию **8E1** (чётность even, 1 стоп-бит); без чётности — **8N2**. На
  деле многие приборы выпускаются с **8N1**, и это работает с большинством
  мастеров.
- **Адрес прибора** — уникальный на линии.

Если хоть один параметр не совпадает, прибор молчит — для мастера это
выглядит как [таймаут](../troubleshooting.md#timeout). Найти адрес
неизвестного прибора помогает [сканер](../guide/scanner.md), а скорость —
перебор по [этой инструкции](../guide/scanner.md#unknown-baud).

## Пример: чтение двух регистров { #example }

Мастер просит прибор с адресом 1 прочитать 2 holding-регистра, начиная с
адреса 0:

```text
01 03 00 00 00 02 C4 0B
|  |  +-+-+ +-+-+ +-+-+
|  |    |     |     +-- CRC16
|  |    |     +-------- количество регистров: 2
|  |    +-------------- начальный адрес: 0x0000
|  +------------------- функция 03: чтение holding-регистров
+---------------------- адрес прибора: 1
```

Прибор отвечает:

```text
01 03 04 41 C4 CC CD 3B 67
|  |  |  +----+----+ +-+-+
|  |  |       |        +-- CRC16
|  |  |       +----------- 4 байта данных: 0x41C4, 0xCCCD
|  |  +------------------- число байт данных: 4
|  +---------------------- функция 03
+------------------------- адрес прибора: 1
```

Два регистра `41C4 CCCD` — это число FLOAT **24.6** в порядке ABCD
(подробнее — [Типы данных и порядок байт](data-types.md)).

### Запись одного регистра

Записать в регистр 1 прибора 1 значение 100 (`0x0064`) — функция 06:

```text
01 06 00 01 00 64 D9 E1
```

Прибор в ответ повторяет запрос байт в байт — это и есть подтверждение
записи.

### Ответ с ошибкой

Если прибор не может выполнить запрос, он отвечает **исключением**: код
функции с установленным старшим битом (`0x03` → `0x83`) и код ошибки:

```text
01 83 02 C0 F1
|  |  |  +-+-+
|  |  |    +-- CRC16
|  |  +------- исключение 02: недопустимый адрес данных
|  +---------- 0x83 = функция 03 + признак ошибки
+------------- адрес прибора: 1
```

Все коды исключений и что с ними делать — в разделе
[Функции и ошибки](functions.md#exceptions).

## RTU, ASCII и TCP

| | Modbus RTU | Modbus ASCII | Modbus TCP |
|---|---|---|---|
| Среда | RS-485, RS-232 | RS-485, RS-232 | Ethernet |
| Формат | двоичный | текстовый (hex-символы) | двоичный |
| Границы кадра | паузы 3,5 символа | символы `:` и CR LF | длина в заголовке |
| Контроль | CRC16 | LRC | нет (это делает TCP) |
| Адрес прибора | в каждом кадре | в каждом кадре | Unit ID в заголовке MBAP |

Набор функций и регистров у всех трёх одинаковый — отличается только
«упаковка». Как устроен Modbus TCP — порт 502, заголовок MBAP, Unit ID — в
разделе [Modbus TCP](tcp.md); как опрашивать приборы RS-485 через сеть — в
разделе [RTU по TCP и преобразователи](rtu-over-tcp.md).

## В ModbusReader

ModbusReader работает мастером Modbus RTU через любой COM-порт или
USB-RS-485 адаптер, а также по [Modbus TCP](tcp.md). Каждый кадр с
разбором полей виден в журнале обмена внизу окна; любой кадр можно
отправить вручную из [консоли](../guide/console.md) — CRC программа
посчитает сама. В режиме [эмулятора](../guide/slave.md) программа сама
становится подчинённым прибором, а [сниффер](../guide/sniffer.md) слушает
чужой обмен, не вмешиваясь.
