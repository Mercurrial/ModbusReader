# Типы данных и порядок байт

Регистр Modbus — это 16 бит, и всё. Протокол не знает, что внутри: число со
знаком, без знака, половина FLOAT или два символа строки. Это знает только
документация прибора — и карта регистров, в которой вы указываете **тип**.

## Типы в ModbusReader

| Тип | Регистров | Что это | Диапазон / пример |
|---|:---:|---|---|
| `BOOL` | 1 | Бит 0/1: coil, discrete input или флаг | 0, 1 |
| `SHORT` | 1 | Целое со знаком, 16 бит (INT16) | −32768…32767 |
| `UINT16` | 1 | Целое без знака, 16 бит (WORD) | 0…65535 |
| `BITS16` | 1 | 16 флагов, показывается в двоичном виде | `0b0000 0000 0010 0101` |
| `BCD16` | 1 | 4 десятичные цифры в BCD | `0x1234` → 1234 |
| `LONG` | 2 | Целое со знаком, 32 бита (INT32, DINT) | ±2 147 483 647 |
| `UINT32` | 2 | Целое без знака, 32 бита (DWORD, UDINT) | 0…4 294 967 295 |
| `BCD32` | 2 | 8 десятичных цифр в BCD | `0x12345678` → 12345678 |
| `FLOAT` | 2 | Число с плавающей точкой IEEE-754 (REAL) | 24.6 |
| `INT64` | 4 | Целое со знаком, 64 бита (LINT) | счётчики энергии |
| `DOUBLE` | 4 | IEEE-754 двойной точности (LREAL) | 3.141592653589793 |
| `STRING` | N | Текст: 2 символа на регистр, длина — в колонке «Размер» | серийный номер |

Остальные типы в списке редактора (`BYTE`, `LONG1`, `FLOAT1`, `FLOAT2`,
`ARR`, `STR_LEN`, `DATE_TIME` и служебные области `UNUSED_AREA`,
`MEMORY_AREA`) нужны для совместимости с картами конкретных приборов и не
опрашиваются как числа — в таблице они показываются как `???` или как область
памяти, которую можно открыть двойным щелчком.

!!! tip "Знак имеет значение"
    Если счётчик после 32767 вдруг становится −32768 — у него тип `SHORT`,
    а нужен `UINT16`. То же для 32 бит: `LONG` ↔ `UINT32`.

**Строки** хранятся по два байта на регистр, старший байт — первый символ;
кодировка — Windows-1251, так что кириллица читается. Строка заканчивается на
первом нулевом байте; при записи остаток поля заполняется нулями.

## Порядок байт { #byte-order }

32-битное значение занимает два регистра, и стандарт Modbus не говорит, в
каком порядке их класть. Каждый производитель решил по-своему. Обозначим
байты числа буквами: **A** — старший … **D** — младший. Тогда число
FLOAT **24.6** = `0x41C4CCCD` (A=`41`, B=`C4`, C=`CC`, D=`CD`) может прийти
четырьмя способами:

| Порядок | Регистр 1 | Регистр 2 | Другие названия |
|---|---|---|---|
| **ABCD** | `41C4` | `CCCD` | Big-endian, «стандартный» |
| **BADC** | `C441` | `CDCC` | Byte swap — байты внутри слова переставлены |
| **CDAB** | `CCCD` | `41C4` | Word swap — слова переставлены (часто у ПЛК) |
| **DCBA** | `CDCC` | `C441` | Little-endian, полный разворот |

Если выбрать не тот порядок, получится не ошибка, а **другое число**. Те же
два регистра `41C4 CCCD`, прочитанные как BADC, дают −775.2, как CDAB —
−107 613 728, как DCBA — −429 426 720. Неправильный порядок почти всегда даёт
очень большое, очень маленькое или отрицательное число там, где его быть не
должно.

Для 16-битных значений вариантов два: **AB** (стандарт) и **BA** (байты
переставлены).

### Где настраивается

**Настройки → Подключение → Кодеки — порядок байт**, отдельно для трёх
семейств:

| Настройка | Действует на | По умолчанию |
|---|---|---|
| SHORT (16 бит) | SHORT, UINT16, BITS16, BCD16, STRING | AB |
| LONG (32 бита) | LONG, UINT32, BCD32, INT64 | ABCD |
| FLOAT (32 бита, IEEE-754) | FLOAT, DOUBLE | **BADC** |

Порядок общий для всей карты и сохраняется в проекте вместе с параметрами
связи.

!!! note "Почему FLOAT по умолчанию BADC"
    Так устроен протокол приборов, для которых программа писалась
    изначально. Если ваш прибор отдаёт FLOAT в стандартном порядке ABCD,
    поменяйте настройку один раз и сохраните проект.

### Как подобрать порядок

1. Найдите регистр, значение которого вы знаете: уставку, напряжение
   питания, температуру в комнате.
2. Переключайте порядок FLOAT (или LONG) в настройках и сохраняйте —
   значение в таблице обновится на следующем цикле опроса.
3. Правильный порядок даёт правдоподобное число; остальные три — мусор.

Сырые слова регистра видны в журнале обмена внизу окна: щёлкните по
зелёной точке у регистра, чтобы видеть в журнале именно его кадры.

## 64-битные значения

`INT64` и `DOUBLE` занимают четыре регистра и следуют тем же настройкам:
`INT64` — порядку LONG, `DOUBLE` — порядку FLOAT. ABCD — восемь байт от
старшего к младшему, BADC — байты переставлены в каждом слове, CDAB —
слова в обратном порядке, DCBA — полный разворот.

## Масштаб и смещение { #scaling }

Многие приборы передают дробные величины целым числом: 573 вместо 57.3 %,
2412 вместо 24.12 В. В карте регистров у каждого регистра можно задать
**инженерные единицы** (в редакторе — «Инженерные единицы…»):

```text
отображаемое = сырое × множитель + смещение
```

Например, множитель `0.1` превратит 573 в **57.3**, а множитель `0.01` и
единица «В» превратят 2412 в **24.12 В**. Масштаб действует в таблице, на
графиках, дашборде, в логгере и снимках. При записи из таблицы и дашборда
программа делает обратный пересчёт: вы вводите 25.5 — в прибор уходит сырое
значение.

!!! warning "Макросы работают с сырыми значениями"
    `read()` в макросе возвращает число так, как его прислал прибор (573, а
    не 57.3), и `write()` пишет его без пересчёта. Масштаб в макросе
    применяйте сами: `read("Мощность нагревателя") * 0.1`.

## Перечисления

Для регистров режима и состояния можно задать подписи значений — по одной
на строку:

```text
0 = Стоп
1 = Работа
2 = Авария
```

Тогда вместо `1` в таблице будет **«Работа»**, а на дашборде виджет
«Выбор» покажет список режимов.
