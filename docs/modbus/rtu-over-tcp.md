# RTU по TCP и преобразователи

Чтобы опрашивать прибор с RS-485 по сети, между ним и компьютером ставят
**преобразователь RS-485 ↔ Ethernet** (его ещё называют сервером
последовательных портов или шлюзом). Он умеет работать в двух режимах, и от
режима зависит, как к нему подключаться.

!!! note "В ModbusReader"
    Текущая версия ModbusReader работает с прибором через COM-порт.
    Подключение по сети — «Modbus TCP» и «RTU по TCP» — готовится к выпуску в
    следующей версии.

## Два режима преобразователя

| | Прозрачный режим | Шлюз Modbus TCP ↔ RTU |
|---|---|---|
| Что идёт по сети | **кадры RTU** как есть — с адресом и CRC | **кадры Modbus TCP** с заголовком MBAP |
| Как называют | «RTU по TCP», RTU over TCP, transparent, TCP Server | Modbus gateway, «Modbus TCP to RTU» |
| Что делает преобразователь | пересылает байты между портом и TCP | перекладывает MBAP ↔ RTU, считает CRC |
| Адрес прибора | в самом кадре RTU | Unit ID в заголовке MBAP |
| Мастер должен уметь | «RTU по TCP» | обычный Modbus TCP |
| Порт | любой из настроек (часто 23, 4001, 8899…) | обычно 502 |

**Прозрачный режим** («RTU по TCP») — это как длинный удлинитель для
RS-485: мастер шлёт по TCP ровно те байты, что пошли бы в COM-порт, вместе с
CRC. Удобно, когда шлюз ничего не знает о Modbus или нужна полная
совместимость, но мастер должен поддерживать RTU по TCP.

**Шлюз Modbus TCP ↔ RTU** превращает прибор с RS-485 в обычный прибор
Modbus TCP: подойдёт любой мастер Modbus TCP. Unit ID в запросе становится
адресом прибора на линии RS-485.

## Как понять, в каком режиме преобразователь

Подключитесь и отправьте запрос в обоих видах:

- ответ пришёл на запрос **Modbus TCP** (`00 01 00 00 00 06 01 03 00 00 00 02`) —
  это шлюз;
- ответ пришёл на голый **кадр RTU** (`01 03 00 00 00 02 C4 0B`) — прозрачный
  режим. На запрос Modbus TCP он обычно молчит: преобразователь отправляет
  заголовок MBAP в линию как есть, и прибор его не понимает;
- нет ответа ни на то, ни на другое — проверьте скорость и чётность в
  настройках преобразователя и адрес прибора.

Разобрать ответ можно в [онлайн-инструменте](../tools/crc.md): он узнаёт и
кадры RTU, и кадры Modbus TCP.

## Настройка преобразователя

Что бы ни стояло, настраиваются одни и те же вещи:

1. **Сетевой адрес** преобразователя — в той же подсети, что и компьютер.
2. **Режим работы** — TCP Server (компьютер подключается к преобразователю),
   и протокол: прозрачный или Modbus TCP.
3. **Порт** — его вы укажете в мастере.
4. **Параметры последовательного порта** — скорость, чётность, стоп-биты —
   **как у прибора**. Мастер их не задаёт: по сети они не передаются.
5. **Таймауты**: время ответа прибора и интервал упаковки кадра (packing
   interval / frame interval) — по умолчанию обычно подходят; на медленных
   приборах таймаут увеличивают.

### USR-TCP232-410S

По умолчанию преобразователь имеет адрес **192.168.0.7**, работает в режиме
**TCP Server** на порту **23** и принимает до 8 клиентов — это прозрачный
режим, «RTU по TCP». Чтобы он работал шлюзом Modbus TCP ↔ RTU, в его
настройках включается преобразование в **ModbusTCP**; порт для него обычно
меняют на 502. Подробности — в [руководстве
производителя](https://www.pusr.com/download/M4/USR-TCP232-410S_User_Manual_V1.0.0.pdf).

### Moxa NPort и MGate

**NPort** — серверы последовательных портов: в режиме **TCP Server** они
работают прозрачно (по умолчанию порт данных 4001) — это «RTU по TCP».
**MGate** — шлюзы Modbus: прибор с RS-485 за ним виден как обычный прибор
Modbus TCP, Unit ID — его адрес на линии.

## Частые проблемы

- **Соединение есть, прибор молчит** — не совпадают скорость или чётность в
  настройках преобразователя, не тот адрес прибора (Unit ID), перепутаны A и
  B на стороне RS-485.
- **Ответы через раз** — маленький таймаут в преобразователе или мастере;
  несколько мастеров через один прозрачный канал мешают друг другу.
- **Соединение сбрасывается** — превышено число клиентов преобразователя или
  он закрывает соединение без активности; мастер должен переподключаться.

Протокол Modbus TCP подробно — в разделе [Modbus TCP](tcp.md), подключение к
RS-485 — в разделе [Подключение к прибору](../connect.md).
