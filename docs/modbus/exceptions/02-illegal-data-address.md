# Исключение 02 — Illegal Data Address

**Исключение 02** (Illegal Data Address, «недопустимый адрес данных»)
означает: прибор получил запрос, понял функцию, но **регистра или бита с
таким адресом у него нет** — или запрошенный блок `начальный адрес +
количество` выходит за пределы существующих.

Это самая частая ошибка Modbus при наладке нового прибора. Хорошая
новость: связь работает — прибор вас слышит и отвечает.

```text
01 83 02 C0 F1
|  |  |
|  |  +-- исключение 02: Illegal Data Address
|  +----- 0x83 = ответ с ошибкой на функцию 03
+-------- прибор 1
```

## Причины — от самой частой { #causes }

### 1. Адрес сдвинут на единицу { #off-by-one }

В документации регистры часто нумеруют с единицы: «регистр 1», «40001»,
а в кадре адрес считается с нуля. Регистр «40001» — это адрес **0**,
«40100» — адрес **99**.

**Проверить:** уменьшите адрес на 1. Если документация даёт адреса с нуля
(часто в hex: `0x0000`), наоборот — не вычитайте ничего.

### 2. Нотация 4xxxx взята целиком { #notation }

«40108» — это не адрес 40108, а «holding-регистр № 108». Цифра 4 означает
таблицу, а не часть адреса. В запрос идёт 107.

**Проверить:** уберите префикс 4/3/1/0 и вычтите единицу. Перевести
адрес помогает [онлайн-инструмент](../../tools/address.md); подробно —
[Области и адреса](../addressing.md).

### 3. Hex прочитан как десятичное число { #hex }

Адрес `0x0100` — это 256, а не 100. Документация, где адреса даны в hex без
приставки `0x` («регистр 1000h» или просто «1000» в колонке «Hex»), —
частый источник ошибки.

### 4. Не та таблица { #table }

Регистр есть, но в другой таблице: измерение лежит в input-регистрах
(читать функцией [04](../functions/04-read-input-registers.md)), а
запрос идёт функцией [03](../functions/03-read-holding-registers.md) —
или наоборот. У многих приборов таблицы 3x и 4x независимы, и один и тот
же номер в них — разные данные.

### 5. Блок выходит за край или задевает «дыру» { #block }

Запрос «прочитать 10 регистров с адреса 95», когда у прибора их всего 100
(0…99), заденет несуществующие 100–104 — и весь запрос получит
исключение 02, хотя первые пять регистров есть. Многие приборы так же
отказывают, если в середине блока есть неиспользуемый адрес.

**Проверить:** прочитайте один регистр — начальный. Ответил — уменьшайте
блок или разбейте его на непрерывные участки.

### 6. Многорегистровое значение прочитано не с начала { #partial }

FLOAT или INT32 в регистрах 100–101: часть приборов отдаёт его только
целиком, начиная с 100. Запрос с адреса 101 или длиной 1 даст исключение
02.

### 7. Регистр только для чтения { #read-only }

Запись функцией 06 или 16 в регистр, который можно только читать,
некоторые приборы отвергают исключением 02 (другие — 03 или 01).

### 8. Регистр «закрыт» паролем или режимом { #locked }

Служебные регистры часто доступны только после записи пароля или в
определённом режиме (например, остановленный привод). До этого прибор
отвечает, будто их нет.

## Как найти верный адрес { #find }

1. Прочитайте **один** регистр, адрес которого точно известен из
   документации (например, серийный номер или версию прошивки).
2. Получилось — сравните со своей картой: насколько сдвинуты адреса?
3. Не получилось — попробуйте тот же адрес ±1 и другую функцию (03 ↔ 04).
4. Если документации нет — переберите адреса автоматически: сканер
   регистров покажет, какие адреса прибор отдаёт.

## В ModbusReader { #modbusreader }

Исключение 02 видно в журнале обмена с адресом запроса, а регистр в
таблице получает статус ошибки. Режим **«Регистры»** [сканера](../../guide/scanner.md)
перебирает адреса и показывает, какие из них прибор отдаёт, — так находится
реальная карта прибора без документации. При [импорте карты](../../guide/map-editor.md)
из Excel или CSV программа спрашивает формат адресов (4xxxx, с единицы или
с нуля) — это убирает смещение на единицу.
