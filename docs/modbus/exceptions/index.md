# Исключения Modbus

**Исключение** (exception) — ответ прибора «понял, но выполнить не могу».
Он приходит, когда кадр дошёл без искажений (CRC верна), адресован этому
прибору, но запрос невозможно выполнить: нет такой функции, нет такого
регистра, недопустимое значение.

Исключение — хорошая новость: **связь есть**, прибор слышит и отвечает.
Проблема в запросе, а не в проводах.

## Как выглядит ответ с ошибкой { #format }

Вместо обычного ответа прибор отправляет три поля PDU: код функции с
установленным **старшим битом** (к коду прибавлено 0x80) и один байт кода
исключения.

```text
01 83 02 C0 F1
|  |  |  +-+-+
|  |  |    +-- CRC16
|  |  +------- код исключения: 02
|  +---------- 0x83 = функция 03 + 0x80 (признак ошибки)
+------------- адрес прибора: 1
```

| Запрошенная функция | Код в ответе с ошибкой |
|:---:|:---:|
| 01 / 02 / 03 / 04 | 81 / 82 / 83 / 84 |
| 05 / 06 | 85 / 86 |
| 15 (0x0F) / 16 (0x10) | 8F / 90 |

В [Modbus TCP](../tcp.md) то же самое идёт после заголовка MBAP — без
CRC.

## Все коды { #codes }

| Код | Название | Что значит | Что проверить |
|:---:|---|---|---|
| [01](01-illegal-function.md) | Illegal Function | Прибор не поддерживает эту функцию | Функцию из документации: 03 или 04, 06 или 16 |
| [02](02-illegal-data-address.md) | Illegal Data Address | Нет регистра с таким адресом или блок выходит за край | Смещение на единицу, hex/dec, таблицу, длину блока |
| [03](03-illegal-data-value.md) | Illegal Data Value | Недопустимое значение или количество | Диапазон уставки, количество регистров, формат кадра |
| [04](04-server-device-failure.md) | Server Device Failure | Внутренняя ошибка прибора при выполнении | Состояние прибора, датчики, документацию |
| 05 | Acknowledge | Принято, но выполняется долго | Спросить позже — так отвечают на долгие операции (запись файла, прошивка) |
| [06](06-server-device-busy.md) | Server Device Busy | Прибор занят другим делом | Повторить позже, увеличить паузу между запросами |
| 08 | Memory Parity Error | Ошибка памяти при чтении файловой записи | Только для функций 20/21; прибор неисправен |
| 0A | Gateway Path Unavailable | Шлюз не может связаться с сетью за ним | Настройки шлюза: порт RS-485, маршрут для Unit ID |
| 0B | Gateway Target Device Failed to Respond | Шлюз отправил запрос, но прибор за ним молчит | Unit ID = адрес прибора, его связь со шлюзом, таймаут шлюза |

В старых документах исключения 04 и 06 называются **Slave Device Failure**
и **Slave Device Busy** — после замены терминов «master/slave» на
«client/server» в 2020 году их переименовали; коды те же.

## Исключение, таймаут или ошибка CRC? { #vs-timeout }

Не каждая неудача — исключение:

| Что видит мастер | Что произошло | С чего начать |
|---|---|---|
| **Исключение** | Прибор получил запрос и отказал | Адрес, функция, значение — см. таблицу выше |
| **Таймаут** — ответа нет | Прибор запрос не получил, не узнал свой адрес или отбросил кадр с неверной CRC | Порт, скорость, чётность, адрес прибора, проводка A/B |
| **Ошибка CRC** — ответ искажён | Ответ пришёл, но повреждён по дороге | Помехи, терминаторы, общий провод, два мастера на линии |

Разбор таймаутов и ошибок CRC — в разделе
[Решение проблем](../../troubleshooting.md).

## Исключения и шлюзы { #gateways }

Коды 0A и 0B появляются только там, где между мастером и прибором есть
**шлюз** — например, Modbus TCP → RTU. Шлюз отвечает сам от имени прибора:

- **0A** — шлюз вообще не знает, куда переслать запрос (не настроен
  маршрут или порт RS-485 занят и недоступен).
- **0B** — шлюз переслал запрос в линию RS-485, но не дождался ответа.
  Это «таймаут за шлюзом»: проверьте Unit ID (он должен совпадать с
  адресом прибора на линии), скорость и чётность порта шлюза и сам прибор.

Подробнее о шлюзах и преобразователях — [RTU по TCP и
преобразователи](../rtu-over-tcp.md).

## В ModbusReader { #modbusreader }

- В журнале обмена — строка ошибки с номером исключения и разбором кадра.
- В [статистике линии](../../guide/register-map.md) — счётчик
  **«Исключения Modbus»**, отдельно от таймаутов и ошибок CRC.
- В [сканере](../../guide/scanner.md) прибор, ответивший исключением,
  помечен **«Жив (исключение)»** — он есть на линии, просто не отдал
  регистр 0.
- В [сниффере](../../guide/sniffer.md) кадры-исключения подсвечены.
- В режиме [эмулятора](../../guide/slave.md) ModbusReader сам отвечает
  исключениями: 01 на неподдерживаемые функции, 02 на адреса вне своей
  карты, 03 на неверное количество или длину. Удобно, чтобы проверить, как
  ваша SCADA или контроллер переживает ошибки.
