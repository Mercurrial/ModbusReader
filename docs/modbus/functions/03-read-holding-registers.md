# Функция 03 — Read Holding Registers

**Функция 03** (0x03, Read Holding Registers) читает подряд один или
несколько **holding-регистров** — 16-битных слов таблицы 4x. Это самая
используемая функция Modbus: в holding-регистрах приборы держат уставки,
настройки, а многие — и измеренные значения.

| Свойство | Значение |
|---|---|
| Код | 3 (0x03) |
| Таблица | Holding registers (4x) |
| Действие | Чтение |
| За один запрос | 1…125 регистров |
| Широковещательно (адрес 0) | Нет — на чтение никто не ответит |

## Запрос { #request }

| Поле | Байт | Значение |
|---|:---:|---|
| Адрес прибора | 1 | 1…247 |
| Код функции | 1 | `03` |
| Начальный адрес | 2 | 0x0000…0xFFFF, старший байт первым |
| Количество регистров | 2 | 1…125 (0x0001…0x007D) |
| CRC16 | 2 | младший байт первым |

Прочитать у прибора 1 три регистра начиная с адреса 0x006B (107; в
нотации Modicon — 40108):

```text
01 03 00 6B 00 03 74 17
|  |  +-+-+ +-+-+ +-+-+
|  |    |     |     +-- CRC16
|  |    |     +-------- количество: 3
|  |    +-------------- начальный адрес: 0x006B
|  +------------------- функция 03
+---------------------- адрес прибора: 1
```

## Ответ { #response }

| Поле | Байт | Значение |
|---|:---:|---|
| Адрес прибора | 1 | тот же, что в запросе |
| Код функции | 1 | `03` |
| Число байт данных | 1 | 2 × количество регистров |
| Значения регистров | 2 × N | каждый регистр — старший байт первым |
| CRC16 | 2 | |

```text
01 03 06 02 2B 00 00 00 64 05 7A
|  |  |  +-+-+ +-+-+ +-+-+ +-+-+
|  |  |    |     |     |     +-- CRC16
|  |  |    |     |     +-------- регистр 0x006D = 0x0064 = 100
|  |  |    |     +-------------- регистр 0x006C = 0x0000 = 0
|  |  |    +-------------------- регистр 0x006B = 0x022B = 555
|  |  +------------------------- 6 байт данных
|  +---------------------------- функция 03
+------------------------------- адрес прибора: 1
```

Каждый регистр — 16 бит без знака. Что это за число — целое со знаком,
половина FLOAT, значение с множителем 0,1 — протокол не говорит: это
написано в карте регистров прибора. Как собирать 32-битные значения из двух
регистров — [Типы данных и порядок байт](../data-types.md).

## Ошибки { #exceptions }

| Ответ | Исключение | Когда |
|---|:---:|---|
| `01 83 01 80 F0` | 01 | Прибор не поддерживает функцию 03 (бывает у приборов, где всё лежит в input-регистрах) |
| `01 83 02 C0 F1` | 02 | Нет регистра с таким адресом — или блок `начало + количество` выходит за край |
| `01 83 03 01 31` | 03 | Количество 0 или больше 125 |
| `01 83 04 40 F3` | 04 | Прибор не смог прочитать значение |

Код функции в ответе с ошибкой — `0x83`: старший бит означает
«исключение». Подробно о каждом коде — [Исключения](index.md#exceptions).

## На практике { #notes }

- **Адрес сдвинут на единицу.** Самая частая причина исключения 02:
  в документации «регистр 40108», а в запрос надо ставить 107 (0x006B).
  См. [Области и адреса](../addressing.md).
- **Не та таблица.** Если на 03 прибор отвечает исключением 02 по
  адресу из документации — возможно, это input-регистр, и читать его надо
  [функцией 04](04-read-input-registers.md).
- **«Дыры» в карте.** Многие приборы отказывают (исключение 02), если в
  запрошенный блок попал хотя бы один несуществующий регистр. Читайте
  такие карты несколькими запросами по непрерывным участкам.
- **Меньше 125.** Часть приборов не отдаёт и 125 регистров за раз — предел
  указан в их документации (бывает 16, 32, 64).
- **Чтение «половинки».** Если FLOAT занимает регистры 100–101, а прочитать
  только 101 — получится мусор, а некоторые приборы ответят исключением.

## В ModbusReader { #modbusreader }

Регистры с областью **4x Holding** в [карте регистров](../../guide/map-editor.md)
программа читает функцией 03 — каждый своим запросом, по кругу. Кадр
запроса и ответа с разбором виден в журнале обмена, а отправить свой кадр
03 можно из [консоли](../../guide/console.md). В режиме
[эмулятора](../../guide/slave.md) ModbusReader сам отвечает на 03, а
[сниффер](../../guide/sniffer.md) расшифровывает чужие запросы и ответы.
