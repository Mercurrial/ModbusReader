# Modbus TCP

**Modbus TCP** — тот же Modbus, только по Ethernet: регистры, функции и коды
исключений те же, что в [Modbus RTU](index.md), меняется «упаковка». Его
поддерживают ПЛК, счётчики, частотники с сетевой картой и шлюзы
RS-485 ↔ Ethernet.

!!! note "Modbus TCP в ModbusReader"
    Щёлкните по параметрам связи в шапке окна и выберите **Modbus TCP**:
    IP-адрес, порт и Unit ID — [Подключение по сети](../connect.md#tcp).
    Там же эмулятор по TCP и поиск приборов в сети.

## Порт 502

Прибор Modbus TCP — это **сервер**: он слушает TCP-порт и ждёт подключения.
Стандартный порт — **502**. Мастер (клиент) подключается к IP-адресу прибора
и этому порту и шлёт запросы по открытому соединению.

- Порт можно сменить в настройках прибора — тогда в мастере нужен тот же.
- Защищённый вариант, **Modbus/TCP Security** (TLS), использует порт **802**.
- В Linux и macOS программы без прав администратора не могут слушать порты
  ниже 1024, поэтому эмуляторы часто ставят на **1502**.

## Кадр: заголовок MBAP + PDU

В отличие от RTU, в кадре Modbus TCP **нет CRC** (целостность обеспечивает
TCP) и **нет пауз** между кадрами: длину кадра сообщает заголовок **MBAP** из
7 байт.

| Поле | Байт | Смысл |
|---|:---:|---|
| Transaction ID | 2 | Номер запроса; ответ приходит с тем же номером |
| Protocol ID | 2 | Всегда `00 00` — Modbus |
| Length | 2 | Сколько байт идёт дальше: Unit ID + PDU |
| Unit ID | 1 | Адрес прибора за шлюзом (см. ниже) |
| PDU | до 253 | Код функции и данные — как в RTU |

### Пример: чтение двух регистров

Запрос — прочитать 2 holding-регистра с адреса 0, Unit ID 1:

```text
00 01  00 00  00 06  01  03 00 00 00 02
|      |      |      |   +-- PDU: функция 03, адрес 0x0000, количество 2
|      |      |      +------ Unit ID: 1
|      |      +------------- длина: 6 байт дальше
|      +-------------------- Protocol ID: 0 (Modbus)
+--------------------------- Transaction ID: 1
```

Ответ:

```text
00 01  00 00  00 07  01  03 04 41 C4 CC CD
                         +-- функция 03, 4 байта: 0x41C4 0xCCCD (FLOAT 24.6)
```

Тот же запрос в Modbus RTU — `01 03 00 00 00 02 C4 0B`: вместо MBAP — адрес
прибора впереди и CRC в конце. Разобрать любой кадр, RTU или TCP, можно в
[онлайн-инструменте](../tools/crc.md).

## Unit ID: какой ставить

**Unit ID** — однобайтовое поле, которое досталось Modbus TCP от адреса
прибора в RTU. Прибор в сети и так находится по IP-адресу, поэтому:

- **Прибор с собственным Ethernet** (ПЛК, счётчик) обычно Unit ID
  игнорирует. Спецификация рекомендует ставить **255** (`0xFF`), но многие
  приборы отвечают только на **1** или на свой адрес Modbus — смотрите
  паспорт.
- **Шлюз Modbus TCP ↔ RTU** передаёт Unit ID как **адрес прибора на линии
  RS-485** за собой: Unit ID 5 — это прибор с адресом 5.
- Если прибор молчит при верных IP и порте — попробуйте Unit ID 1, 255 и 0.

## Чем TCP отличается от RTU

| | Modbus RTU | Modbus TCP |
|---|---|---|
| Среда | RS-485 / RS-232, витая пара | Ethernet, Wi-Fi, любые IP-сети |
| Адрес прибора | 1–247 в каждом кадре | IP-адрес (+ Unit ID) |
| Граница кадра | пауза 3,5 символа | длина в заголовке MBAP |
| Контроль ошибок | CRC16 | контрольные суммы TCP |
| Мастеров на линии | один | несколько клиентов одновременно |
| Запросы | строго по очереди | несколько сразу, по Transaction ID |
| Расстояние | до ~1200 м по RS-485 | любое — через сеть и маршрутизаторы |
| Скорость | 9600–115200 бод | 10/100 Мбит/с, ограничивает прибор |

Регистры, [адресация](addressing.md), [типы данных и порядок
байт](data-types.md) и [коды исключений](functions.md) в TCP точно такие
же: карта регистров прибора не зависит от того, как к нему подключаться.

## Если не подключается { #not-connecting }

| Что видно | Причина |
|---|---|
| **Соединение отклонено** (connection refused) | IP верный, но порт закрыт: другой номер порта или Modbus TCP в приборе выключен |
| **Таймаут соединения** | Неверный IP, прибор в другой подсети, мешает брандмауэр |
| Соединение есть, **ответа нет** | Не тот Unit ID; за шлюзом — неверная скорость или чётность RS-485 |
| **Исключение** в ответе | Связь в порядке, не тот адрес регистра или функция — см. [коды ошибок](functions.md) |
| Ответ есть, но «не Modbus» | На порту другой протокол — например, преобразователь в режиме [RTU по TCP](rtu-over-tcp.md) |

Многие приборы держат только **одно-два соединения**: если к прибору уже
подключена SCADA, второй мастер может получить отказ.
