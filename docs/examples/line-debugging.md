# Отладка линии RS-485

Связь «то есть, то нет» — самая неприятная проблема на объекте. ModbusReader
даёт три инструмента, чтобы разобраться: **статистику линии**, **журнал
обмена** и **сниффер**.

## Шаг 1. Посмотрите на статистику

Подключитесь и дайте опросу поработать минуту-две, затем щёлкните по
статистике в правом нижнем углу.

| Картина | Что это значит | Куда смотреть |
|---|---|---|
| Ответов 0 из N | Прибор не слышит или не отвечает | [Шаг 2](#silent) |
| Доля ответов 90–99 %, есть таймауты | Связь есть, но ненадёжна | [Шаг 3](#unreliable) |
| Много ошибок CRC | Ответы приходят искажёнными | [Шаг 3](#unreliable) |
| Есть исключения | Связь в порядке, проблема в запросах | [Шаг 4](#exceptions) |
| Время ответа растёт | Прибор перегружен или медленный | Увеличьте паузу между запросами |

Счётчики обнуляются при каждом подключении и кнопкой **«Сбросить»** —
сбросьте их после каждого изменения, чтобы видеть эффект.

## Шаг 2. Прибор молчит { #silent }

Проверяйте по порядку — от простого:

1. **Порт.** Тот ли COM-порт? Адаптер мог получить новый номер в другом
   USB-разъёме.
2. **Адрес прибора** в строке состояния (`ID: 1`).
3. **Скорость, чётность, стоп-биты** — как в приборе. Неизвестны —
   [сканер](../guide/scanner.md#unknown-baud).
4. **Полярность A/B.** Поменяйте провода местами — это безопасно и
   помогает чаще, чем кажется.
5. **Питание прибора** и включён ли у него Modbus (у некоторых приборов
   интерфейс включается в меню).
6. **Таблица регистров.** Если в карте есть хотя бы один регистр, который
   прибор знает, ответ придёт. Проверьте из
   [консоли](../guide/console.md) самым простым запросом:
   `01 03 00 00 00 01` — прочитать один регистр с адреса 0. Исключение в
   ответ — уже успех: прибор на связи.

## Шаг 3. Связь есть, но со сбоями { #unreliable }

**Ошибки CRC** — ответ пришёл, но искажён:

- нет **общего провода (GND)** между адаптером и прибором;
- длинная линия без **терминаторов** 120 Ом на концах;
- провод — не витая пара, или линия идёт рядом с силовыми кабелями и
  частотными преобразователями;
- **не та чётность** или скорость близка, но не та;
- на линии **второй мастер** (например, SCADA опрашивает те же приборы) —
  кадры сталкиваются. Проверьте сниффером.

**Таймауты через раз:**

- прибор не успевает: увеличьте **паузу между запросами** (100–200 мс) и
  **таймаут ответа**;
- слабый сигнал на длинной линии: снизьте скорость (например, 115200 →
  19200);
- дешёвый адаптер без автоматического переключения направления.

## Шаг 4. Исключения { #exceptions }

Прибор на связи и отказывает в конкретных запросах. Щёлкните по зелёной
точке у регистра — в журнале будут кадры именно его обмена, — и сверьтесь
с [таблицей исключений](../modbus/functions.md#exceptions):

- **02** — нет такого адреса: смещение на единицу, не та таблица (FC 03 вместо
  04), FLOAT, который «вылезает» за последний регистр прибора;
- **01** — прибор не поддерживает функцию: регистр в другой таблице;
- **03** — недопустимое значение при записи: уставка вне диапазона.

## Шаг 5. Послушайте линию сниффером

Если на линии работает чужой мастер (SCADA, контроллер), подключите
**второй адаптер** параллельно и откройте [сниффер](../guide/sniffer.md):

- запросы есть, ответов нет — прибор не слышит или адрес не тот;
- ответы с **BAD CRC** — помехи на линии, а не ошибка мастера;
- два разных мастера по очереди — конфликт, кадры будут сталкиваться;
- исключения — мастер просит то, чего у прибора нет.

Сниффер ничего не передаёт, поэтому подключать его к работающей линии
безопасно.

## Если ничего не помогло

Сохраните журнал обмена (**«Сохранить журнал…»**), снимите скриншот
статистики и создайте вопрос в
[Discussions](https://github.com/Mercurrial/ModbusReader/discussions) — с
моделью прибора, адаптера и параметрами связи.
