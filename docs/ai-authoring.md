# Создание карт и макросов с ИИ

В репозитории есть автономный skill **modbusreader-authoring** для Claude и
ChatGPT/Codex. Он помогает создавать карты регистров, проекты, дашборды и макросы
по спецификации устройства, а затем проверяет файлы без подключения к оборудованию.

## Получить skill

Из корня репозитория, Python 3.10+ (сторонние библиотеки не нужны):

```text
python tools/build_authoring.py --zip dist/modbusreader-authoring.zip
```

Архив содержит одну папку `modbusreader-authoring` с `SKILL.md`, справочником,
примерами и автономным валидатором. При изменении версии приложения пересоберите
архив; версии схем и API находятся в `references/contract.json`.

- **Claude.ai:** загрузите ZIP в раздел пользовательских Skills; для запуска
  валидатора необходима возможность выполнения кода.
- **Claude Code:** скопируйте папку skill в `.claude/skills/` проекта или
  `~/.claude/skills/` пользователя.
- **ChatGPT/Codex:** используйте раздел Skills вашего клиента; доступные способы
  импорта зависят от клиента и рабочего пространства. Для локального Codex папку
  можно разместить в `.agents/skills/` проекта или `~/.agents/skills/` пользователя.
- Если обычный чат не поддерживает установку Skills, приложите `SKILL.md` и
  справочник как контекст. Это не установка skill; без инструмента Python модель
  сможет только проверить спецификацию вручную и не должна заявлять об успешном CLI.

Установка в аккаунты не выполняется сборщиком. Инструкции платформ:
[OpenAI](https://learn.chatgpt.com/docs/build-skills),
[Claude](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview).

Пример запроса:

> Используй modbusreader-authoring. По приложенной спецификации составь карту
> регистров ModbusReader и макрос десяти измерений с интервалом 1 с. Для каждого
> адреса укажи источник. Если порядок байтов или база адресации не определены,
> уточни их. Проверь файлы валидатором, макрос не запускай.

## Команды без ИИ

```text
python -m core.authoring_cli describe
python -m core.authoring_cli schema profile
python -m core.authoring_cli validate map.json
python -m core.authoring_cli validate project.mbproj
python -m core.authoring_cli validate panel.mbdash --profile map.json
python -m core.authoring_cli check-macro measurement.py --profile map.json
python -m core.authoring_cli completions --profile map.json --language ru
```

В `--profile` разрешён также текущий `.mbproj`. Команды печатают JSON в stdout;
для сохранения схемы используйте перенаправление `> profile.schema.json`.
Пути диагностики — JSON Pointer; строка и столбец Python считаются с 1.

Коды завершения: **0** — нет ошибок; **1** — ошибки проверки; **2** — ошибка
чтения, разбора файла или аргументов команды. `--warnings-as-errors` возвращает
1 также при предупреждениях. Поле `valid` зависит только от ошибок. Ошибки
синтаксиса самой команды выводятся argparse в stderr; диагностика файлов — JSON.
Входной файл ограничен 8 MiB. Проверка не меняет файлы, не открывает порты и
не исполняет скрипты. Нужен только стандартный Python.

## Что проверяется

Структура, версии, поля и типы; адресные границы и размер значений; совместимость
типов с областями; повторные адреса и неоднозначные имена; привязки и порты
дашбордов; синтаксис и общий с runtime AST-фильтр макросов; аргументы известных
прямых вызовов API и буквальные ссылки на регистры.

Перекрывающиеся диапазоны — предупреждение: это может быть намеренный alias.
Динамические обращения, методы объектов регистров, пользовательские функции,
длительность циклов и соответствие реальному устройству требуют отдельной
проверки. Валидатор не является интерпретатором Python или изолированной средой
исполнения. Успешная проверка не означает, что макрос можно запускать на устройстве.

Это строгий контракт **создания текущих файлов**. Старые карты, которые приложение
загружает через миграции, могут не проходить его. CLI не заменяет загрузчики и
не исправляет сомнительные адреса/типы автоматически.

Для проверки, как приложение загрузит существующий проект вместе с макросами
из его папки, используйте `python tools/check_project.py project.mbproj`.
Примеры проектной структуры и подготовки файлов находятся в `AI_GUIDE.md`
в корне репозитория.

## Общий источник данных

- `core/macro_api.py`: API, встроенные функции, AST-фильтр, подсказки. Этот же
  реестр использует MacroRunner и справка редактора.
- `core/authoring.py`: построение схем из реестров приложения и семантическая проверка.
- `schemas/*.schema.json`: автономные JSON Schema 2020-12 для внешних редакторов.
- `schemas/macro-api.pyi`: объявления для языковых инструментов; не импортировать
  их из самого макроса.
- [Справочник контракта](reference/authoring.md): генерируется вместе со skill.

В редакторе макросов **Ctrl+Space** предлагает функции; внутри первого строкового
аргумента `reg`, `read`, `write` — имена регистров актуальной карты. Это первые
подсказки от общего контракта, не полноценный языковой сервер.

После изменения исходного контракта:

```text
python tools/build_authoring.py
python tools/build_authoring.py --check
python -m pytest tests/test_authoring.py tests/test_macro_engine.py tests/test_macro_safety.py
```

`--check` и тест распаковки ZIP предотвращают расхождение документации, схем,
runtime и автономной копии валидатора. Проверка архива запускает его в отдельном
каталоге с отключёнными site-packages, без доступа к установленным Qt/ModbusReader.
